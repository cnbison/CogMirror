# CogMirror 项目完整流程文档

> 编程学习认知教练 —— 从做题到"认知地图"的完整技术与业务链路
> 本文档基于对 `CogMirror-main` 源码（`cogmirror/` 包 + PRD/治理文档）的通读整理，目标是让人不看代码也能完整理解这个项目"做了什么、为什么这么做、每一步怎么算出来的"。

---

## 0. 项目一句话定位

**CogMirror** 是一个面向"成年自学编程者"的命令行工具：用户做 Python 基础题，系统在**判分之外**，用一套认知科学框架（Bloom + SOLO + 5D + BKT + MIRT）把用户的"真实认知状态"计算出来，画成一张**认知地图**，并明确指出三件多数刷题工具不说的事：

1. **伪自信**：你自己觉得"稳了"的题，实际上没做对；
2. **临界概念（liminal）**：你正卡在"从不会到会"的过渡期，这是正常现象不是退步；
3. **一句话建议**：下一步具体做什么，而不是一份长学习计划。

它是 ECOS（一个更早、面向 K12 的"教育认知操作系统"）项目复盘收缩后的产物：**只服务成年自学者学 Python 这一个垂直场景**，代码大量迁移自 ECOS 但做了大幅精简（详见第 9 节）。

每次用户答一道题，都会依次触发：**判分 → 历史累积 → BKT 更新 → MIRT 联合估计 → Bloom 分布更新 → misconception 检测 → 临界概念检测 → 伪自信检测 → 综合置信度与轨迹快照**，八个步骤严格按顺序执行（`belief_engine.BeliefEngine.update()` 的 Step 1-8）。这条链路是全项目的核心，后面会逐步展开。

## 2. 理论基础：为什么是这几套模型

产品设计上明确"不是拍脑袋定的框架"，PRD 第 8b 节专门审查了理论依据：

### 2.1 Bloom 六层认知分类法（任务类型的粗分类）

题目按认知复杂度分成六层，从易到难：

| 层级 | 名称 | 含义 | 题库难度参数 |
|---|---|---|---|
| L1 | Remember 记忆 | 记住术语/语法 | -1.0 |
| L2 | Understand 理解 | 理解语义 | -0.3 |
| L3 | Apply 应用 | 用已知解决标准问题 | +0.3 |
| L4 | Analyze 分析 | 拆解/找错 | +1.0 |
| L5 | Evaluate 评价 | 比较方案优劣 | +1.6 |
| L6 | Create 创造 | 独立写出新程序 | +2.2 |

这个"难度参数"直接喂给 MIRT 模型作为题目的 `difficulty`（见 `questions.py` 的 `BLOOM_DIFFICULTY`）。

**已知局限（PRD 明确承认）**：学术界发现 Bloom 分类法用在编程教育上，评分者间一致性差，容易只照顾"平均水平学生"。因此引入 SOLO 分类法作为补充（结构观察学习结果：前结构/单一结构/多元结构/关联结构/抽象拓展），专门捕捉"知道多个知识点但没关联起来"的中间状态——这正好和临界概念（TC）的设计目标重合，但**当前代码尚未实现 SOLO 层，只是理论上确认了它是 TC 机制的学术支撑**。

### 2.2 5D 认知框架（K/P/S/C/X）

五个维度对应认知/教育心理学中已有的经典知识类型划分：

| 维度 | 全称 | 核心问题 | 理论出处 |
|---|---|---|---|
| K | Knowledge 知识 | 我知道什么？ | Anderson ACT-R 陈述性知识 |
| P | Procedure 程序 | 我能做什么？ | 程序性知识 |
| S | Strategy 策略 | 我应该怎么做？ | Paris 条件性知识 |
| C | 概念联结/置信度 | 这些知识如何连接？/自我评估准不准 | 图式理论 / 元认知（见下方说明） |
| X | 元认知/外部支架 | 我如何知道自己是否知道？ | Flavell 元认知 |

**这里有一个重要的"理论 vs 代码实现"落差，PRD 第 8b 节专门做了澄清**：

- 理论上 5D 应该是"潜变量层"：C = 概念联结、X = 元认知，是真正要画进认知地图的认知状态；
- 但**当前代码里 C 实际装的是"置信度/伪自信"，X 目前完全没有可用的观测来源**——这是 ECOS 遗留的操作性实现，描述的是"可观测信号"而非"认知结构本身"；
- 团队的决策是：**先诚实标注，不强行改名字**。C 维度现在同时承载了校准（伪自信）+ misconception + 临界概念三种信号（PRD 称之为"构念污染"），等 Phase 0.5 对话式诊断验证了"概念联结"确实可测之后，才会重构 C/X 的推断逻辑；X 维度因为 MVP 没有支架/提示机制，地图上直接显示"暂未测量"而不是编一个假数值。

这个设计哲学贯穿全项目：**没有观测数据支撑的维度，宁可显示"暂未测量"，也不用先验值冒充"测出来的结果"**（后面会反复看到这个原则，比如 `print_map` 里 C/X 的展示逻辑）。

### 2.3 BKT（Bayesian Knowledge Tracing，贝叶斯知识追踪）

经典 4 参数模型（Corbett & Anderson, 1994），按**知识点（skill_id）粒度**追踪掌握概率，是比 MIRT 更细粒度、更贴近单个知识点学习曲线的模型。

### 2.4 MIRT（多维项目反应理论）

用来在**5 个维度上联合估计**用户的能力值 θ（连续实数），是比 BKT 更宏观、跨知识点整合的模型。BKT 管"某个知识点学得怎样"，MIRT 管"五维能力画像整体是什么样"，两者不是互斥而是不同粒度的互补。

### 2.5 Threshold Concept（临界概念，TC）

来自教育学理论：某些概念一旦真正理解就会带来"世界观质变"（如"变量是标签不是盒子"），跨越过程中会经历一个"似懂非懂"的过渡态（liminal），这个过渡态不是退步，是正常的学习中间态。TC 理论天然带三个特性：**不可逆、变革性、整合性**。

## 3. 题库设计（内容层）

### 3.1 题库结构

题库是**纯静态、纯代码维护**的，不依赖任何 LLM 生成或判分——这是相对 ECOS（题目由 LLM 生成、LLM 判分）的一个刻意选择，换来的是**结果可复现、无 API 依赖、partial credit 由测试用例通过率自然产生**，代价是内容需要人工编写、扩展慢。

- **规模**：51 题，覆盖 5 个 topic（`python.variables` 变量赋值 / `python.loops` 循环 / `python.functions` 函数 / `python.recursion` 递归 / `python.scope` 作用域）× Bloom L1-L6 全六层。
- **文件**：`cogmirror/questions.py`（`_bank()` 函数里硬编码全部题目对象）。

### 3.2 题型与判分逻辑（`grade()` 系列函数）

| 题型 | 判分方式 | 分数区间 |
|---|---|---|
| `choice` 单选 | 选项下标与标准答案比对 | 1.0 或 0.0（无 partial credit）|
| `fill` 填空 | 文本标准化（去空格转小写）后精确匹配可接受答案集合 | 1.0 或 0.0 |
| `code` 写函数 | **本地真实执行**用户代码，跑一组测试用例，`score = 通过用例数 / 总用例数` | 连续 partial credit |

`code` 题判分的关键工程细节：

- 用 `exec(user_code, namespace, namespace)`，**globals 和 locals 用同一个 dict**——这是自测中发现的坑：如果拆成两个独立 dict，递归函数的 `__globals__` 会落到独立命名空间，导致正确的递归代码被误判 `NameError`。
- 用 `signal.alarm` 做**超时保护**（默认 5 秒），防止死循环/死递归的用户代码卡死整个判分流程，超时会被明确标注"疑似死循环"。
- 语法错误、运行时异常都被 catch 并转成友好的中文错误提示，而不是让 traceback 直接抛给用户。
- 少数题目（闭包类，如 `make_counter`、`make_adder`）因为**返回值本身是一个函数**，无法用"输入参数-比对返回值"的通用测试用例结构表达，单独写了 `_grade_make_counter` / `_grade_make_adder` 特判逻辑：实际调用返回的闭包函数并检验其行为。

### 3.3 MIRT 载荷（loadings）设计——题库设计中最关键的一环

每道题在声明时都要标注它在 5 个维度上的**区分度**（loadings），例如：

```python
loadings={"K": 1.2}          # 纯记忆题，主要考 K
loadings={"K": 1.0, "S": 0.4} # 既考知识又略微考策略判断
loadings={"P": 1.2, "S": 0.4} # 写代码题，主要考程序技能
```

**为什么载荷是必需的，而不是可选的美化项**：代码注释里明确写了——如果所有题目都用默认参数（各维度载荷相同），MAP 后验估计在维度间是完全对称的，数学上必然导致**五维 θ 全部相等**，5D 画像直接退化成 1D。这是 Phase 0 阶段真实踩过的关卡问题（"实测发现"）。载荷设计的经验规则：

- 记忆/再认类题 → 主要载荷在 K
- 写代码题 → 主要载荷在 P
- 找错/分析/比较类题 → 主要载荷在 S

未声明载荷的题目会兜底给一个 `[0.8]*5` 的默认向量（`QuestionBank.mirt_items()`），避免游离题目破坏估计。

### 3.4 题目讲解设计

- **选择题**：每个选项都配一句讲解（`option_explanations`），不只是告诉用户"错了"，而是解释为什么选的这个选项错、正确项为什么对——这是产品迭代中新增的功能（29 道选择题已补齐逐选项讲解）。
- **填空/写码题**：配一句知识点讲解（`explanation`），判分后展示。

## 4. 完整业务流程：一次 `cogmirror` 运行的生命周期

以命令 `cogmirror`（等价于 `python -m cogmirror.cli`）为例，逐步拆解 `main()` 函数的执行顺序：

### 步骤 1：初始化

1. 解析命令行参数（`--user` / `--db` / `--questions` / `--topic` / `--level` / `--map-only` / `--review` / `--export` / `--delete`）。
2. `--export` / `--delete` 是独立分支，直接走数据合规命令（见第 7 节），不进入答题流程。
3. 加载静态题库 `QuestionBank()`；连接 SQLite（`Database`）；确保用户记录存在（`ensure_user`）。
4. **P4 误解证据闭环初始化**：从数据库加载历史 misconception 证据计数，注入 `MisconceptionTracker`，再传给 `BeliefEngine`——这一步决定了本次会话里"误解命中"的置信度不是固定值，而是基于该用户历史证据动态计算的。
5. 把题库的 MIRT 参数（载荷+难度）批量注册进引擎的 MIRT 模型。

### 步骤 2：恢复或创建用户状态

- 如果是新用户：创建初始 `BeliefState`（5 维 θ 全部为 0，协方差为单位阵），打印欢迎语和上手说明。
- 如果是老用户：从最近一次 `belief_snapshots` 恢复完整状态；同时**重新从全部历史作答记录（responses 表）重建引擎内部的响应历史**（因为 MIRT 估计需要完整历史，而不是只有上次快照）。
- **P2 自评校准曲线**：基于历史全部作答记录重新计算校准曲线（每次会话都重算，不落库，是"派生视图"而非持久化状态）。
- **P3 间隔衰减视图**：基于历史记录重放每个知识点的"历史峰值掌握概率"，再按 Ebbinghaus 遗忘曲线算出"当前衰减后的掌握概率"，用于后面判断是否需要复测提醒。
- **P5 纵向档案**：按快照时间聚类切分会话（相邻快照间隔 > 30 分钟算新会话，一次运行内的多轮练习聚为同一会话），聚合出两样东西--「上次卡住的 skill」（上次会话 score < 0.6 的知识点）和「最近 n 个会话末的 K/P/S 首末对比」（趋势）。都是纯派生视图，不落库。
- 打印"进度概览"（上次主导 Bloom 层级 + 正在跨越中的临界概念）和"上次卡住"（P5：让相关历史在会话开始时主动浮现，而不是等用户自己去翻）。

### 步骤 3：选题（`run_session`）

按以下顺序过滤候选题：
1. 如果是 `--review` 错题重练模式：只取"该题最近一次得分 < 60%"的题目集合；
2. 如果指定了 `--topic`：只保留该 topic 的题；
3. 如果指定了 `--level`：只保留该 Bloom 层级的题；
4. 截取前 `n_questions` 道。

### 步骤 4：单题作答循环（每题都会走这一整套）

对每道题依次执行：

1. **打印题面**。
2. **答题前自评置信度**：问"你有多大把握答对？（0-100，可跳过）"，转成 0-1 浮点。这一步是**伪自信检测的输入源**——不采集自评就无法检测伪自信。
3. **读取答案**：根据题型分别处理（选择题校验编号合法性、填空题直接读、写码题多行读到 `END`）。
4. **判分**：`bank.grade_answer()` 返回 `(score, details)`。
5. **可选追问"为什么这么答"**（仅在 `score < 0.6` 时触发）：这是 **P4 阶段新增的功能**——在此之前，misconception 检测在产品路径上从未真正触发过（因为检测逻辑依赖用户的解释文本，而之前的产品流程里根本不采集这段文本）。用户可以跳过（回车），跳过是常态。
6. **展示判分详情与讲解**：代码题展示每个测试用例的通过情况；选择题展示所选选项的讲解；填空/写码题展示知识点讲解。
7. **构造 `Observation` 对象**，交给 `BeliefEngine.update()` 做核心的信念更新（见第 5 节详细展开）。
8. **落库**：把这次作答（含分数、Bloom 层、自评、是否命中伪自信、是否命中某个 misconception）写入 `responses` 表。
9. **逐题实时反馈**（不是等到最后看地图才知道）：
   - 如果这道题让某个"临界概念"发生了状态变化（推进/回落/跨越），当场打印一行提示；
   - 如果这道题命中了新的"伪自信"，当场打印一行提示（自评 vs 实际得分的对比）。

### 步骤 5：认知地图渲染（`print_map`）

一组题答完后（或 `--map-only` 直接跳过答题），渲染完整地图，包含以下分节（详见第 6 节）：

1. **整体解读**（一段综合性文字，不是数字，是"人话"；P5 起在答题会话末还可能追加一句"本次变化 + 为什么"的证据锚定反思句）
2. **5 维状态**（K/P/S/C/X 各自的掌握概率条形图）
3. **自评校准度（ECE）**（数据量足够才显示）
4. **与上次相比**（如果有上一次的状态可对比）
5. **Bloom 六层分布**
6. **伪自信点**（逐条列出）
7. **误解点**（逐条列出，附检测置信度）
8. **临界概念**（正在跨越中 / 已跨越）
9. **复习提示**（间隔衰减检测到"曾掌握、正在遗忘"的知识点）
10. **近几次趋势**（P5：≥2 个会话末的 K/P/S 首末对比，样本不足不显示）
11. **一句话建议** + 可直接复制执行的命令

### 步骤 6：建议驱动的连续练习循环

地图展示完后，系统会计算一个"建议练习目标"（`suggested_practice`），如果存在，就询问用户"要不要现在就按建议练 3 道题"，用户同意则再跑一轮 `run_session`，答完重新渲染地图（因为状态变了，临界概念可能刚好跨越）。如此循环直到没有建议或用户拒绝。

### 步骤 7：收尾——误解证据对账与落库

本次会话新增的作答记录会拿去和 `MisconceptionTracker` 做**对账**（`reconcile`）：如果某题命中了某个 misconception，看同一知识点下一次作答是否重蹈覆辙——重蹈覆辙则"这个检测被证实"，答对且未重触发则"这个检测被证伪"。对账结果更新证据计数，写回数据库，供下次会话使用（下次误解命中的置信度会因此变化）。

## 5. 核心引擎：`BeliefEngine.update()` 逐步拆解

这是全项目算法密度最高的一段代码，每次作答都会依次跑完以下 8 步（对应 `belief_engine.py`）：

### Step 1：响应历史累积

把这次作答（题号、是否判对、分数、Bloom 层、自评、答案）追加进该用户的内存历史列表（`_response_history`），最多保留最近 100 条（`HISTORY_MAXLEN`），作为下一步 MIRT 估计的输入。

**"是否判对"的派生规则**：`correct = score >= 0.6`。也就是说 partial credit 分数不是原样使用，而是有一个二值化的判对阈值——这个 0.6 阈值被反复复用于 BKT、伪自信检测、误解对账等多个环节，是全项目统一的语义约定（代码注释标注"ECOS v0.54.0 语义"，说明这个阈值是从上一代产品沿用下来的经验值）。

### Step 2：BKT 更新（知识点粒度）

用经典 4 参数贝叶斯更新公式：

- 若本题答对：
  `P(L|correct) = P(L_prev)(1-slip) / [P(L_prev)(1-slip) + (1-P(L_prev))·guess]`
- 若本题答错：
  `P(L|wrong) = P(L_prev)·slip / [P(L_prev)·slip + (1-P(L_prev))·(1-guess)]`
- 再叠加"学习转移"：
  `P(L_new) = P(L|obs) + (1 - P(L|obs)) · p_learn`

默认参数：`p_init=0.1, p_learn=0.1, p_guess=0.2, p_slip=0.1`（Corbett-Anderson 经典论文默认值），每个知识点（`skill_id`，比 topic 更细，如 `python.variables.assignment`）独立维护一条 BKT 曲线。

### Step 3：MIRT MAP 估计（联合 5D 能力值）

这是数学上最重的一步。目标是给定该用户全部历史作答（分数序列 + 对应题目的载荷/难度），求一个 5 维能力向量 θ，使得**后验概率最大**：

- **似然模型**（logistic）：`P(答对|θ, 题目) = sigmoid(a_specialized · θ + a_general · mean(θ) - difficulty)`，其中 `a_specialized` 是该题在 5 维上的载荷向量，`a_general` 是一般因子权重（用 5 维均值近似一个"总体能力"因子，这是简化的 Bi-factor 结构）。
- **先验**：θ ~ N(0, I)（冷启动先验，均值 0、协方差单位阵）。
- **优化**：用 `scipy.optimize.minimize`（L-BFGS-B）最小化负对数后验（似然项+先验项），得到 MAP 估计 `theta_hat`。
- **不确定性估计**：用数值 Hessian 矩阵求逆近似后验协方差 `theta_cov`，对角线做非负保护。

估计出的 θ 向量再转换成每个维度的：
- `theta`（原始能力值，可正可负）
- `se`（标准误，= sqrt(协方差对角线)）
- `mastery_prob = sigmoid(theta)`（转成 0-1 概率，更适合人看）
- `mastered = mastery_prob >= 0.5`
- `confidence = 1/(1+se)`（标准误越小，系统对这个估计越有信心）

**这一步只有在历史作答 ≥ 2 条时才触发**（少于 2 条无法有效估计，保持初始 0 值）。

### Step 4：Bloom 六层分布更新

不是重新估计，而是**增量调整**：`delta = (score - 0.5) * 2 * step`，`step = 0.12`（这个步长值是自测调出来的——早先用 0.05 时六层数值差异太小，"全对也挤在 0.5-0.65 之间"，用户根本看不出六层的区分度）。同时记录"这一层已经有观测过"（`covered_layers`），因为**主导层级只能从有观测的层里选**——否则一个只做过 L1/L2 题的新手，会因为 L5/L6 停留在先验 0.5 而被误判成"主导层级是创造层"。

### Step 5：误解（misconception）检测 → C 维度折扣

如果用户在"为什么这么答"追问里写了文本，就用**关键词匹配**（非 LLM）在 8 条 misconception 库里找命中最多关键词的条目。命中后：
- 记录一条 `MisconceptionHit`；
- 该误解的"置信度"不是固定的，而是由 `MisconceptionTracker.confidence()` 算出的 **Laplace 平滑证据置信度**：`(success+1)/(success+failure+2)`——如果这个误解在该用户身上反复被证实（下次同知识点还是错），置信度会持续走高；如果被克服（下次答对且没重触发），置信度回落。首次遇到、无历史证据时回退到固定值 0.5，`BeliefEngine` 层面还有一个额外的固定回退 0.6（当 tracker 未注入时，比如测试环境）。
- 折扣公式：`discount = 1 - min(confidence * 0.3, 0.3)`，累乘进 `state.C.discount_factor`（持久化的折扣因子，最大值封顶 1.0）。

### Step 6：临界概念（TC）状态检测

见第 6.4 节的状态机详细说明。

### Step 7：伪自信检测

如果用户填了自评置信度，计算 `gap = 自评 - 实际得分`。当**自评 ≥ 0.7 且 gap ≥ 0.5** 时，判定为一次"伪自信命中"（`IllusoryConfidenceHit`），并且：
- 折扣幅度不再是写死的 0.15，而是走**校准曲线驱动**（详见 5.5 节）：查该用户在这个自评置信度所在的"历史真实答对率"，`discount = 1 - expected_accuracy`（夹在 [0.05, 0.5] 之间）；曲线数据不足（该桶样本 < 5）时回退固定值 0.15。
- 折扣同样累乘进 `state.C.discount_factor`。

### Step 8：C 维度最终掌握概率、整体置信度与轨迹快照

`state.C.mastery_prob = sigmoid(theta_C) × discount_factor`——**这一行必须放在每次更新的最后**，因为 Step 3 的 MIRT 每次都会整体重算 5 个维度的 `mastery_prob`，如果伪自信/误解折扣不在最后重新应用一次，会被 MIRT 的结果覆盖掉。

`overall_confidence` = 5 个维度 `confidence`（即估计的确定性，非掌握概率）的均值。

最后把当前完整状态打一个快照（`StateSnapshot`）追加进轨迹（`trajectory`），最多保留 500 条，用于未来做成长曲线可视化。

## 6. 认知地图的关键机制细节

### 6.1 校准曲线（P2，`calibration.py`）—— 让伪自信折扣"用数据说话"

原理：把用户历史全部自评置信度按 0.1 宽度分桶（如 [0.3,0.4) 一个桶），统计每个桶里"真实答对率"（`(correct+1)/(n+2)`，Laplace 平滑，因为单用户数据稀疏，不平滑会出现 0% 或 100% 的极端值）。

**用途一**：查询"自评 X% 的题，历史上实际答对率是多少"（`expected_accuracy`），驱动伪自信折扣幅度。

**用途二**：计算 **ECE（Expected Calibration Error，期望校准误差）**——衡量整体自评准不准的一个数字，`Σ(桶样本占比 × |真实率-预测率|)`，越接近 0 说明自评越靠谱。地图上的"自评校准度（ECE）"这一行就是这个值，样本不足 5 次时诚实标注"数据不足"而不是硬算一个不可靠的数字。

### 6.2 间隔衰减复测（P3）—— Ebbinghaus 遗忘曲线

- **历史峰值重放**（`peak_mastery_from_history`）：因为 BKT 状态不持久化（重启后只从响应历史恢复 MIRT 输入，不恢复 BKT 内部状态），"这个知识点曾经掌握到多高"这个信息需要**从头重放一遍历史作答**，用临时 BKT 模型逐条 update，记录过程中出现过的最高 `P(L)` 值。
- **无状态衰减公式**：`decayed = peak × e^(-days/τ)`，`τ` 默认 30 天。这里特意强调是"无状态"（直接套公式，而不是在已经衰减过的值上再乘一次衰减因子），避免"每次打开都衰减一次"导致的复合衰减错误。
- **复测触发条件**（双条件，保守）：`峰值 ≥ 0.7`（曾经真的掌握过）且（`衰减后 < 0.55` 或 `跌幅 ≥ 0.15`）——避免"从没学好过"或"衰减不明显"的知识点被误报成复测提醒。

### 6.3 误解证据闭环（P4，`misconception_tracker.py`）

核心是一个**预测-对账**模式（Prediction Reconciler）：

- "检测到某个 misconception"本质上是一个预测——"这个学习者有这个误解"；
- 对账时看**同一知识点的下一条作答**：如果又错了或者又命中同一个误解 → 预测被证实（`record_success`，注意这里 success 指的是"检测这个预测本身"被验证正确，不是学习者答对）；如果答对且没再命中 → 预测被证伪（`record_failure`，可能是误报或已被克服）；
- 置信度公式同样是 Laplace 平滑：`(success+1)/(success+failure+2)`；
- 对账窗口**严格限制在同一次会话新增的记录内**，不会跨会话追溯全部历史——因为"下一条响应"如果隔了很久（比如几天后才再做同知识点的题），"下一条响应能反映当时误解是否还在"这个假设就不成立了。

### 6.4 临界概念状态机（`tc.py`）

三态：`pre_liminal → liminal → post_liminal`，**post_liminal 不可逆**（一旦跨越，状态机不再退回）。

- **`pre_liminal → liminal`**：需要"L3+（Apply 及以上）答对 + 当前无 active misconception"，每次满足累加 progress（+0.3），达到阈值 0.7 进入 liminal；
- **`liminal → post_liminal`**：需要**连续 3 次** L3+ 答对（`post_liminal_streak = 3`），中途只要答错一次，"连续计数"清零、progress 回落，但**不会退出 liminal 状态**——这是为了呼应产品文案"这不是退步，是学习的正常中间态"；
- 每个 topic 有一条独立的 TC 定义（5 个 topic 对应 5 条 TC，如"变量是标签而非盒子"），定义存放在 `tc.DEFAULT_TC_LIBRARY`，同时 `content/threshold_concepts.py` 里有一份更详细的教学内容版本（前概念/liminal 信号/后概念/跨越指标），CLI 展示名统一以 `tc.py` 里的库为准，避免两处文案漂移。

### 6.5 "诚实标注"设计原则贯穿地图渲染

`print_map` 函数里反复出现这个模式：**没有足够观测就不编造数值**——

- X 维度：MVP 没有支架/提示机制，直接显示"暂未测量"；
- C 维度：没有伪自信命中证据时，不显示一个先验值（如 0.55），而是显示"未发现失准"或"暂无自评数据"（自测中发现，数值 0.55 会被用户误读成"中等自信"，实际上语义是"数据不够，谈不上准不准"）；
- ECE：样本 < 5 时显示"数据不足"而不是硬算；
- Bloom 未覆盖的层：显示"暂无对应层级题目，暂未测量"，而不是显示先验 0.5。
- 维度差距判断（"知识强于程序技能"这类结论）：只有当 `MIRT 已生效（作答≥2次）` 且**相对差距 ≥0.15、且较高的一侧本身 ≥0.6**（真正达到"确实掌握"的水平）才下结论——真机测试发现过一个坑：全错的学习者 P=0.40 > K=0.24，如果只看相对差距会得出"程序技能比知识更扎实"这种荒谬结论，所以加了绝对水平的门槛。

### 6.6 一句话建议的决策优先级（`next_suggestion` / `suggested_practice`）

按固定优先级依次判断，命中即返回：

1. **有临界概念正在 liminal** → 建议做 3 道该概念的应用题（L3），并明确"不建议现在学新概念"（教育学里的"合意困难"原则：巩固已经触碰到的临界概念，而不是分散注意力）；
2. **有知识点命中间隔衰减复测条件** → 建议先做复测题；
3. **已练习过的知识点里 BKT 掌握概率最低的** → 建议巩固该项（若最弱项都 ≥0.7 则说明已练概念掌握良好，建议开新 topic）；
4. **完全没有历史数据** → 提示"先完成一组题"。

`practice_command` 会把这个建议直接翻译成一条可复制执行的 CLI 命令（如 `cogmirror --topic python.loops --level L3 --questions 3`），做到"建议即可执行"，不需要用户自己去拼参数。

### 6.7 纵向档案与会话反思（P5，`session.py` + `map_interpretation` 扩展）

让认知地图从"本次快照"变成"纵向连续"，两个部件：

- **上次卡点召回**（`last_session_struggles`）：会话边界按快照时间聚类（间隔 > 30 分钟分界），"上次会话"=最后一个聚类。窗口有一个容易被忽视的细节：起点放宽到**上一聚类的末快照**，因为真实时序是先作答、后存快照--会话内的作答发生在该会话首快照之前，如果窗口从首快照起算会把整个会话的作答都漏掉。欢迎行的「上次卡住：循环、作用域」就是这个函数的输出。
- **跨会话趋势**（`multi_session_trend`）：取最近 n（默认 3）个会话各自的末条快照，解析 state_json 里的 K/P/S `mastery_prob` 组成序列，输出首末值。少于 2 个会话返回空（单点无法谈趋势），地图的 [近几次趋势] 段随之不显示。
- **会话反思句**（B2，`map_interpretation` 的可选参数 `prev_state` + `session_rows`）：有"与上次相比 delta"且本次有作答时，追加一句「本次 K 知识: +12%（50% -> 62%）--2 道记忆/理解层题答对」。归因按 Bloom 层切分（K<-L1/L2、P<-L3、S<-L4+，各层对错计数可直接回溯到 responses）。两个克制的守卫：①**归因只在方向一致时给出**--维度上升归因答对、下降归因答错；真机测试发现 MIRT 全历史重估可以让 K 在本会话答对的情况下仍然下降，这时"答对"配"下降"是自相矛盾的误导，宁可只报变化不归因。②无 delta / 无作答 / `--map-only`（无 prev_state）一律不出反思句，不声称"本次有变化"。

## 7. 数据与隐私设计

数据库是本地 SQLite（`data/cogmirror.db` 默认路径），三张表：

| 表 | 内容 |
|---|---|
| `users` | 用户 ID、创建/活跃时间、数据导出请求时间、删除请求时间 |
| `responses` | 每一次作答的完整记录（题号/知识点/分数/是否判对/Bloom层/自评/是否伪自信/答案原文/命中的误解ID/时间戳）|
| `belief_snapshots` | 每次答题后完整 `BeliefState` 的 JSON 快照（用于恢复与轨迹）|
| `misconception_evidence` | 每条误解模式的证据计数（success/failure），跨会话持久化 |

**成人向合规设计**（相对 ECOS 面向未成年人的监护人同意框架，这里换成标准成人数据合规）：

- `--export`：导出该用户全部数据为 JSON（含用户信息、全部作答、误解证据）；
- `--delete`：删除该用户全部作答与快照数据，需要用户显式输入 `DELETE` 二次确认，不可逆；
- 产品文案要求明确"这是学习状态画像，不是心理测评"，避免用户产生"被诊断"的误解。

## 8. 策略学习模块（P1，预留未接入主流程）

`policy/` 目录下实现了两种经典的轻量 bandit 算法，**当前 MVP 不会调用它们**，是为 Phase 1（验证 P0 后）"学习建议的策略优化"预留的：

- **LinUCB**（Li et al., 2010）：为每个候选题目/推荐 arm 维护线性参数，选择时用 `argmax(θ_a^T x + α√(x^T A_a^{-1} x))` 平衡探索与利用；
- **Thompson Sampling**（Beta-Bernoulli 共轭）：每个 arm 维护 (α, β)，采样 `θ_a ~ Beta(α,β)` 后取最大值对应的 arm；
- **`ab_test.py`**：对同一批历史事件序列，把两种策略各自 replay 一遍，比较平均 reward，用于回答"哪种推荐策略更好"。

明确排除了 ECOS 里更重的 **POMDP+PBVI** 算法——"数据规模不支撑，用简单方法"是 PRD 里写明的取舍。

## 9. 从 ECOS 迁移与收缩的关键决策（帮助理解"为什么这样设计"）

CogMirror 不是从零开始写的，而是从一个更早、面向 K12 场景的"教育认知操作系统"ECOS 项目复盘后收缩重启的。理解这个背景，能解释很多"看起来可以做得更通用，但故意没做"的设计：

- **只服务一个垂直**（成年人自学 Python），明确排除 K12、企业内训、"跨领域通用认知内核"——README 原话："直到 Phase 2 给出明确的正向信号之前，任何'做得更通用一点'的想法都先记进 SOMEDAY.md，不要动手做"；
- **去掉了 ECOS 里的重型基建**：双 Agent 互校机制、LLM Critic 感知层、EventLog/StateEngine 防篡改审计、warm-up 探针题状态机（K12 体验设计）、Goal Ontology、Motivation 系统等，这些在 MVP 阶段被认为是"没有验证支撑的复杂度"；
- **判分方式反向选择**：ECOS 用 LLM 生成题目+LLM 判分，CogMirror 反其道而行，改成静态题库+确定性判分——用可复现性换取灵活性，是经过深思的取舍而非能力不足；
- **命名去身份化**：`student_id` 改成 `user_id`，去掉"学生"这个隐含身份，呼应"面向成年自学者"的定位。

## 10. 已知的技术难题与验证现状（诚实边界）

产品文档非常克制地写明了当前的局限，不虚标：

1. **MIRT/BKT 框架的根本局限**：这套数学体系依赖结构化的"题目-属性矩阵"，只对"做题"这种有明确对错的交互成立。如果要支持开放式对话学习（"我不懂这段代码，帮我看看"），需要一套全新的、从非结构化文本提取认知信号的方法——这不是简单复用现有代码能解决的。

2. **Phase 0.5 对话式诊断技术 Spike 的结论（已收口）**：开发者本人做了 3 轮"先做外部锚点测试、再和 AI 对话估计能力"的对比，方向一致（对话估计 ≈ 锚点或略低，没有系统性高估），但**样本量 n=1，不构成"验证通过"**，5-8 人真人测试轮次被决策推迟。当前结论：静态题库仍是 P0 的核心判分依据，对话式诊断作为增强/技术预研继续，不阻塞主线。

3. **5D 维度间区分度未经验证**：S（策略）与 X（元认知）概念上高度接近，C（概念联结）与 K（知识）边界模糊，理论上存在"有效自由度低于 5 维"的风险，需要更多真实对话数据做相关性分析才能下结论。

4. **真人验证暂缓**：当前全部数据来自开发者自测（不计入正式样本），产品判断 CLI 体验和界面美观度还不够，等项目更完善后才会找 5-10 个非开发者本人的真实用户做正式验证——这也是 ECOS 阶段吸取的教训（"测试者不能是开发者本人"被写成了硬性治理规则）。

## 11. 测试与质量保障

- 全项目 **338 项自动化测试**全部通过（`pytest`）；
- **黄金回归基建（P1）**：7 条合成学习者的完整作答序列 + 数值基线快照，任何引擎行为变更都会自动触发回归比对（`pytest -m regression`），基线更新必须带文档化 diff，防止"改了算法但没人发现输出变了"。
- 这套回归机制在文档中被反复提到"因此黄金回归基线不受影响"，说明团队非常重视**新功能上线不能悄悄改变老用户已有的历史数据解读结果**。

## 12. 一图流：完整交互时序（一次会话）

```
用户运行 cogmirror
   │
   ├─ 加载题库 + 连接DB + 恢复/创建用户状态 + 重算校准曲线/衰减视图
   │    + 纵向档案聚合（上次卡点 / 跨会话趋势，P5）
   │
   ├─ 循环 N 道题：
   │     题面展示 → 自评置信度 → 作答 → 判分(选择/填空/代码)
   │        → [答错时可选]为什么这么答
   │        → BeliefEngine.update():
   │              历史累积→BKT更新→MIRT联合估计→Bloom分布更新
   │              →误解检测(证据置信度)→TC状态机→伪自信检测(校准曲线折扣)
   │              →C维度最终掌握概率→overall_confidence→轨迹快照
   │        → 落库(responses表) → 逐题即时反馈(临界概念/伪自信)
   │
   ├─ 渲染认知地图：整体解读(可含本次反思句)→5维状态→校准ECE→对比上次
   │                →Bloom六层→伪自信点→误解点→临界概念→复习提示
   │                →近几次趋势→一句话建议
   │
   ├─ [可选]按建议连续练习，重渲染地图
   │
   └─ 会话收尾：误解证据对账(reconcile) → 写回misconception_evidence表 → 关闭DB
```
